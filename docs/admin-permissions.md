# 관리자 권한

- 사용자 상세 → 편집에서 최고 관리자가 `songs / clips / users / system`을 복수 선택한다.
- `super_admin`은 모든 권한을 가지며, 이 UI/API로 최고 관리자를 생성하거나 해제할 수 없다.
- 권한 변경은 최고 관리자만 가능하다. 사용자 담당자는 프로필·칭호·활동을 관리하지만 최고 관리자 계정을 수정할 수 없다.

| 권한 | 담당 기능 |
| --- | --- |
| 노래 | 기존 노래 관리 화면, 곡 정보 수정·추가·삭제 |
| 클립 | 클립 관리·신고·생성, 댓글/타임라인, 영상 동기화·변환, 곡 기본 클립 길이 |
| 사용자 | 사용자 목록·상세·활동 조회, 일반 계정 프로필·칭호 관리 |
| 시스템 | 유지보수·백업·재계산·쿠키 설정 및 기존 로컬 관리 도구 |

시스템 권한은 전체 DB 백업을 읽을 수 있는 신뢰 수준이다. DB 복원은 사용자 권한도 과거로 되돌리므로 최고 관리자 전용으로 유지한다.

## 호환성과 보안

- DB의 `adminScopes` 필드가 없으면 기존 노래 관리자/편집자 권한을 유지한다. 기존 편집자의 생성·삭제 제한도 유지된다.
- 필드가 존재하면 기존 role 대신 명시된 권한을 사용한다. 빈 배열은 관리 권한 전체 회수이다.
- 기존 데이터를 일괄 변경하는 마이그레이션은 필요 없다. 프로필만 저장하는 경우 기존 권한을 변환하지 않는다.
- 메뉴·바로가기와 서버 API가 같은 권한 함수를 사용한다. API에서는 role 문자열이 아닌 전체 `session.user`를 전달해야 한다.
- 세션 권한은 매 요청 DB에서 다시 읽는다. DB 조회 실패나 사용자 삭제 시 JWT의 과거 관리자 권한으로 대체하지 않는다.
- 클립 담당자의 곡 기본 길이 변경은 별도 `/api/songdetails/[id]/clip-duration` API로 제한한다. 다른 곡 필드는 수정할 수 없다.
- 노래 관리는 관리자 패널의 노래 탭(`/admin?tab=songs`)에서 사용한다. 기존 `/admin/songs` 주소는 새 탭으로 연결된다.
