# 개인·커뮤니티 클립 구간

## 재생과 편집

- 적용 순서: 본인 개인 설정 → 검증된 공식 구간 → 커뮤니티 추천 → 기존 구간.
- 개인 설정은 다른 사람이나 공유 플레이리스트에 복사하지 않는다. 재생 큐에는 기존 클립 정보만 유지하고 실제 재생 직전에 공통 재생기가 사용자별 구간을 조회한다.
- 재생 중인 구간은 스냅샷으로 고정한다. 다른 사람이 투표하거나 관리자가 수정해도 현재 재생 위치가 갑자기 바뀌지 않는다. 본인이 편집을 적용하거나 다음 재생을 시작할 때 반영한다.
- 상세 팝업, 공유 페이지, 전역 미니플레이어에서 `구간 조정`을 사용한다. 미니플레이어는 펼쳐서 접근한다. 오디오 업로드 재생은 이 기능 대상이 아니다.
- `구간 조정`은 영상을 가리지 않도록 플레이어 아래 별도 조작 줄에 배치한다.
- 일반 사용자 편집 화면은 편집기를 열었을 때 재생하던 클립의 시작을 `0:00`으로 고정한다. 이전 시각은 음수이며 입력·현재 위치·진행바·개선안을 모두 같은 좌표로 표시한다. 탐색 범위나 편집 경계가 바뀌어도 원점은 유지된다. UI에서 상대 시각을 원본 시각으로 변환하므로 재생/서버 저장 데이터 형식은 변경하지 않는다. 관리자 원본 시각 편집은 유지한다.
- 두 경계 모두 `0.1 / 0.5 / 1 / 5 / 10 / 30초`를 지원한다. 초기 선택은 시작 0.5초, 끝 5초. 단위 선택·편집 중간값·미리 듣기는 DB에 기록하지 않는다.
- 편집 탐색 범위는 기존 재생 구간 앞뒤 15초로 시작한다. 끝이 없으면 시작부터 240초를 기준으로 잡는다. 앞/뒤 30초 확장 또는 입력한 경계만큼 확장한다. 원본 전체를 별도 파일로 내려받거나 새 클립 영상 파일을 생성하지 않는다. 실제 스트리밍 버퍼링은 플랫폼 플레이어 동작을 따른다.
- 로그인하지 않으면 이번 재생에만 적용한다. 로그인 후 저장한 개인 구간은 다른 기기에도 적용된다. 기본 구간과 같으면 행을 남기지 않으며, 명시적으로 고정한 경우만 예외다. 개인 설정 삭제로 공식/추천 구간을 다시 따른다.
- 개인 구간 적용·저장에는 종료 시각이 필요하다. 기존 종료 시각이 없는 클립도 편집 후에는 원본 전체가 아닌 명시한 구간만 재생한다.

## 커뮤니티와 관리자

- 미검증 클립의 기본 동작은 `저장하고 공유`다. 공유하지 않으려면 `저장 옵션`을 연 뒤 `공유 없이 나에게만 저장`을 선택한다. 기존 공유 제안이 자동 철회되지는 않는다. 검증 클립은 개인 저장만 지원한다.
- 상시 고정 체크박스는 없다. 개인 설정이 없는 상태에서 구간을 바꾸지 않고 저장하면 그때만 고정 여부를 확인한다. 이미 개인 설정이 있으면 확인을 반복하지 않는다. 공식 구간과 동일한 값은 새 개선안으로 공유하지 않는다. 저장과 공유는 순차 처리하며 공유 실패 시 개인 저장 성공 여부를 안내한다.
- 시작·종료는 독립된 경계다. 시작만 앞당기면 종료 시각은 그대로이고 길이만 늘어난다. 시작이 종료 이상이면 종료를 자동 이동하지 않고 저장/경계 미리 듣기를 막는다.
- 개선안은 정확한 시작·종료 한 쌍이다. 두 제안의 경계를 섞거나 평균내지 않는다. 동일 구간 중복 공유는 기존 제안 ID를 반환한다.
- 제안자 외 3개 계정이 양쪽을 모두 확인하고 문제 제기가 없으면 추천 후보가 된다. 기존 추천은 독립적인 문제 제기 2개부터 해제한다. 확인 수가 같으면 현재 추천을 유지하고, 이후 생성 시각/ID로 결정한다.
- 평가는 사용자·제안당 한 행을 갱신한다. 양쪽 모두 미평가로 돌리면 행을 삭제한다. 자가 평가는 서버에서 거부한다. UI는 해당 경계 10초 미리 듣기 후 평가를 열지만, 이는 청취 사실을 서버에서 증명하거나 다중 계정을 방지하는 장치는 아니다.
- 사용자·클립당 활성 제안 1개, 클립당 활성 제안 최대 50개, 계정당 최근 24시간 새 제안 20개. 동일 제안 재공유는 새 제안으로 세지 않는다. API 인스턴스별 추가 burst 제한은 분당 30회이며 분산 환경의 전역 제한은 아니다.
- 검증된 클립은 제안·평가를 받지 않고 공식값을 재생한다. 개인 설정은 계속 허용한다.
- 관리자 기존 전체/곡별 상세 편집과 생성 클립 검토 화면에 제안 조회·미리 듣기·편집값 가져오기를 추가했다. `현재 편집 구간 공식 저장 및 검증 완료`는 시간과 검증 표시를 한 트랜잭션으로 저장한다. 설명·날짜·URL은 기존 저장 버튼을 사용한다.
- 전체 클립 목록은 `커뮤니티 추천 있음` 필터, 추천 확인 수/끝부분 축소량 정렬을 제공한다.
- 일반 구간 수정은 검증을 해제한다. 공식 시간·검증 변경은 기존 추천을 무효화하되 개인 설정은 유지한다. 원본 영상 ID/플랫폼 변경은 개인 설정까지 무효화한다. 기본 길이 일괄 적용은 검증 클립을 건너뛴다.

## 저장량 및 수명

개인 문서는 `_id, userId, clipId, sourceVersion, startTime, endTime`만 가진다. 제목, URL, 사용자 정보, 이유, 생성/수정일, 재생 이력, 별도 설정 플래그는 저장하지 않는다. `(userId, clipId)` 고유 인덱스로 덮어쓰며 자동 생성하지 않는다.

ObjectId 3개와 소수 경계 2개를 가진 샘플의 BSON 크기는 **117바이트**였다. 같은 형태 10만 건은 원시 문서 약 **11.2 MiB**, 100만 건은 약 **111.6 MiB**다. 이는 인덱스·스토리지 엔진·복제·백업 비용을 제외한 값이며 실제 디스크 사용량이나 요금을 의미하지 않는다. 개인 문서에는 고유 복합 인덱스와 클립 정리용 인덱스만 추가한다.

공유 제안과 평가 데이터는 별도다. 닫힌 제안 및 관련 평가는 90일 후 TTL로 제거하고, 공식 등록 이력은 클립당 최근 20건만 남긴다. 활성 제안/평가는 자동 만료하지 않는다. 클립 삭제 시 연관 구간 데이터도 삭제한다. 계정당 사용자가 실제로 저장한 클립 수와 참여 평가 수에 따라 늘어나므로 무제한 총용량을 보장하는 설계는 아니다.

일반 구간 조회는 클립과 본인 설정을 배치 조회한다(최대 10개). 평가는 쓰기 때 집계하고 추천 요약만 클립에 저장하므로 일반 재생마다 투표를 집계하지 않는다. 클라이언트 캐시는 계정별 키를 사용하고, HTTP 응답은 `private, no-store`다. 서버의 구간 데이터는 재생만으로 기록하지 않는다(기존 재생 수 집계는 별개).

## 운영 전 확인

- MongoDB **replica set 또는 트랜잭션 지원 클러스터**가 필요하다. standalone 서버에서는 저장 트랜잭션이 동작하지 않는다.
- 새 Mongoose 모델의 고유·TTL 인덱스 생성을 확인한다. 기존 클립은 버전 필드가 없어도 0으로 읽으므로 전체 백필은 필요 없다. 운영 DB 마이그레이션/배포는 이 작업에서 실행하지 않았다.
- 공식 구간을 직접 수정하는 새 기능은 `SongVideo.findOneAndUpdate` 경로를 사용해야 한다. 현재 시간 수정 경로와 기본 길이 일괄 적용을 연결했다. raw collection / bulkWrite / updateMany로 시간이나 원본을 변경하면 수명주기 훅을 우회하므로 별도 버전 무효화가 필요하다.
- 저장·평가·공식 등록의 충돌을 같은 클립 문서와 트랜잭션으로 직렬화한다. 오래된 원본/공식 리비전으로 저장하면 충돌 응답을 내고 최신 구간을 다시 불러오게 한다.
- 익명/일반 사용자/관리자 API 권한, 구간 정책, 독립 테스트용 Mongo replica set 통합 테스트를 포함한다. 테스트는 운영 URI를 사용하지 않는다.
- 실제 YouTube/치지직 청취에서 seek 정밀도, 모바일 자동재생 정책, 편집 후 일시정지/재생 복원, 배경 탭의 종료 시점을 배포 전 확인한다. 0.1초 데이터 정밀도가 플랫폼의 샘플 단위 재생 정확도를 보장하지는 않는다. 이번 작업에서는 개발 서버를 띄우지 않아 브라우저 수동 검증은 수행하지 않았다.
