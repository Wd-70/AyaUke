# 노래 관리 워크스페이스

## 확인한 데이터와 표시 규칙

2026-11-15 운영 DB를 읽기 전용으로 확인했다. 전체 571곡 중 활성 570곡, 가사 미등록 85곡, 기본 클립 길이 미설정 488곡이었다. 활성 곡의 MR은 모두 등록되어 있었으며 MR이 여러 개인 곡은 19곡이었다. 표시 제목과 가수가 중복되는 묶음은 2개였다. MR 스킵 0초는 정상값일 수 있으므로 오류나 미완성으로 분류하지 않는다.

노래책은 Google 시트와 DB를 원본 제목·가수로 병합한다. 화면에는 별칭을 우선 표시하며, 표시 제목·가수 조합이 겹치면 한 곡만 노출한다. DB의 등록 경로가 sheet라는 사실만으로 현재 공식 시트에 포함된 곡이라고 단정하지 않는다.

## 구조

- 관리자 패널의 노래 탭: `/admin?tab=songs`
- 기존 `/admin/songs` 북마크는 새 탭으로 연결
- 목록: 원제·표시명·가수·태그 검색, 언어/등록 경로/작업 필터, 최근 수정·제목·가수·클립 수 정렬, 24곡 페이지
- 편집: 기본 정보 / MR·재생 / 가사·메모 / 표시 미리보기
- MR: 복수 링크, 대표 선택, 스킵·버전, 외부 재생 위치 확인
- 일괄 작업: 태그 추가·언어·키 조절, 최대 100곡, 선택 대상 확인
- 보관함: 소프트 삭제·복원, 곡과 클립의 원본 데이터는 삭제하지 않음
- 모바일: 편집창의 스크롤 영역 한 개, 하단 저장 버튼 고정, 이탈 시 미저장 확인

## 데이터 보호

원본 제목·가수는 생성할 때 지정하고 이후에는 표시명만 수정한다. 곡 ID, 클립 연결, 자동 집계값, 관리 화면에서 다루지 않는 레거시 필드는 덮어쓰지 않는다. 참고 메모는 기존 공개 데이터 응답에 포함되므로 비공개 메모로 안내하지 않는다.

신규 API는 `/api/admin/song-library`, `/[id]`, `/bulk`이다. 입력 필드를 명시적으로 검증하고 노래 권한으로 제한한다. 기존 song_editor의 생성·삭제 제한도 유지한다. 저장 시 updatedAt을 비교해 MR/클립 작업과의 충돌을 막고, 일괄 수정에서는 충돌한 곡을 별도로 보고한다. 변경 후 노래책 경로를 재검증한다.

## 검증

- 스키마·검색·MR 선택 유지 단위 테스트
- 폐기 가능한 MongoDB에서 저장·충돌·일괄 처리·보관/복원 통합 테스트
- API 권한·입력 범위·캐시 재검증 테스트
- `scripts/qa/song-library-preview.mjs`: 실제 DB나 인증정보를 사용하지 않는 브라우저 확인용 데이터. 실행 후 `http://127.0.0.1:43219`에서 확인한다.

운영 DB에 대한 테스트 쓰기, 자동 데이터 보정, 배포는 수행하지 않는다.

## YouTube MR 후보 선택

관리자 신규/수정의 MR·재생 탭과 노래책의 곡 정보 편집에서 같은 `MRSearchPicker`를 사용한다. 기존 관리자 편집 컴포넌트도 첫 결과 자동 등록 대신 이 선택기를 사용한다.

- `MR 검색`을 누르면 기본 검색어로 즉시 검색한다. 검색어 수정 후에는 `다시 검색`을 누른다. 화면 진입·언어 변경으로 검색하지 않는다.
- 썸네일, 제목, 채널을 보고 `영상 확인`으로 YouTube를 열거나 `MR 추가`로 편집 목록에 넣는다. 실제 저장은 곡 저장 버튼으로 한다.
- 일본어: 전체 검색 25개 + 떡뮤 채널 검색 10개를 병합·중복 제거하고 떡뮤 후보를 우선 표시한다. 기본 검색은 제목을 포함하지 않는 떡뮤의 다른 곡을 제거한다. 원제/표기가 달라 누락되면 검색어를 직접 바꿀 수 있다(직접 입력한 검색어는 제목 제한을 해제).
- 한국어: 금영·TJ 공식 채널 ID와 공식 노래방 브랜드 채널명으로 제외한다. 영상 제목/설명에 브랜드가 언급됐다는 이유로 독립 제작자의 MR을 제외하지 않는다.
- 같은 영상의 짧은 URL/전체 URL 중복 추가를 차단한다. 완전히 빈 행부터 채우고 기존 MR·대표 선택·스킵은 보존한다. 새 MR의 스킵은 0초이며 직접 확인해야 한다.
- 목록은 부모 화면의 스크롤 영역을 공유한다. 검색어/곡/언어 변경, 접기, 언마운트 시 이전 검색을 취소한다.
- `/api/youtube-search`: 노래 수정 또는 생성 권한 필수, 엄격한 입력 검증, 서버 API 키 사용. `selectedResult` 및 키 정보는 반환하지 않는다. 5분/100개 결과 캐시, 진행 중 요청 병합, 할당량 초과 시 기존 다중 키 순차 재시도, 부분 실패 안내를 제공한다.

채널 ID 확인(2026-11-15): [떡뮤](https://www.youtube.com/@%EB%96%A1%EB%AE%A4), [금영](https://www.youtube.com/channel/UCDqaUIUSJP5EVMEI178Zfag), [TJ](https://www.youtube.com/channel/UCZUhx8ClCv6paFW7qi3qljg). 구현은 [YouTube Search API](https://developers.google.com/youtube/v3/docs/search/list)의 채널 검색을 사용한다.

실제 API 읽기 테스트: Lemon/米津玄師 일본어 검색에서 해당 떡뮤 영상이 최상위, 밤편지/아이유 한국어 검색에서 공식 채널 결과 9개 제외를 확인했다. 후보는 검색 결과이며 MR의 곡·키·버전 일치가 자동 검증된 것은 아니다. 브라우저 편집 테스트에는 가짜 데이터만 사용했다. QA 페이지의 `?songbook&dark`는 노래책 편집/다크 화면을 제공한다.
기존/수동 입력 MR에는 YouTube 영상 썸네일·제목·채널을 표시한다. 영상 정보는 URL의 영상 ID가 바뀔 때만 지연 조회하고 중복 요청/결과를 캐싱한다. 길이 메모 입력란은 제거했으며 기존 데이터는 보존한다. 대표 MR은 저장 후 카드/상세창에 즉시 동기화하고 빈 행 정리 및 삭제 시 영상의 정체성을 유지하도록 인덱스를 보정한다.

## 로딩 최적화

- 목록·상세: 기존 TanStack Query 사용. 계정/권한별 키, 신선도 30초, 미사용 캐시 10분, 포커스 복귀 시 강제 재조회 없음. 호버 120ms / 키보드 포커스·터치 시 관심 곡 상세만 프리페치한다.
- 편집: 캐시된 상세가 있으면 즉시 표시하고 오래된 데이터만 백그라운드 조회한다. 입력 중·저장 중에는 응답이 입력값을 덮어쓰지 않는다. 기존 updatedAt CAS와 409 충돌 안내는 유지한다.
- 통계: 상세 GET은 클립 집계를 하지 않는다. `/api/admin/song-library/[id]/stats`를 미리보기 진입 시 별도로 조회하며 로딩·실패가 편집을 막지 않는다. 서버 집계는 두 count 쿼리 대신 한 aggregate를 사용한다.
- 저장: DB 쓰기 결과로 상세와 목록의 해당 항목만 갱신한다. 진행 중 이전 읽기를 취소해 늦은 응답이 저장 결과를 되돌리지 않게 한다. 표시명 중복 플래그도 재계산한다. 일괄 저장은 갱신된 요약을 반환하고 대상 상세 캐시만 제거한다. 충돌 발생 시에는 실제 목록을 재조회한다.
- 목록 DB 읽기: projection으로 가사·메모 본문을 제외하고 hasLyrics만 계산한다. 전체 클립 집계는 서버 인스턴스에서 30초 캐시/동시 요청 공유한다. 수동 새로고침은 `?fresh=1`로 통계를 새로 집계하며 캐시도 교체한다. 다른 클립 화면에서 발생한 변경은 TTL 이내 지연될 수 있다.
- MR: `/api/youtube/metadata/batch`는 최대 30개 영상 ID를 한 번에 처리한다. 노래 권한 검사 후 요청하며 DB 연결을 하지 않는다. 클라이언트 20ms 배치/중복 제거, 클라이언트·서버 ID별 1시간 캐시, 접근불가 영상은 서버에서 1분 캐시한다. YouTube fetch에도 1시간 Next 캐시를 적용한다. 서버 메모리 캐시는 인스턴스 간 공유되지는 않는다.
- 기존 MR은 입력 대기 없이 조회한다. URL 변경 중에만 350ms 대기한다. 검색 후보를 선택하면 제목·채널을 즉시 캐시에 넣어 별도 메타데이터 요청을 생략한다.

분리된 가짜 서버에서 요청 수 검증: 상세 프리페치 후 열기·재열기의 상세 GET은 합계 1회, 단일·일괄 저장 후 목록 GET 증가 없음, MR 2개는 배치 POST 1회, 검색 선택 MR은 배치 POST 증가 없음. 지연된 응답 도착 후에도 미저장 입력이 유지됐다. 이는 운영 사이트의 실측 응답시간이나 속도 개선율 측정은 아니다.

## 노래책 인라인 편집

보기 모드에서는 기존 상세 기능을 유지한다. 편집 진입 시 영상은 일시정지하고 팝오버를 닫으며, 연필·닫기·좋아요·플레이리스트·OBS·녹음 영역 대신 `곡 정보 수정` 헤더와 기본 정보 / MR·재생 / 가사·메모 탭을 표시한다. 하단 고정 취소·변경 저장만 제공한다. 본문 스크롤은 하나이며 모바일에서는 가장자리 8px 여백과 16px 라운딩을 두고 visualViewport 높이에서 위아래 여백을 뺀 높이를 사용한다.

관리자와 노래책이 `components/song-editor/SongEditorFields.tsx` 및 공통 UI primitives를 공유한다. 노래책은 공개 Song 모델에 없는 기본 클립 길이를 표시하거나 PUT에 전송하지 않아 기존 길이가 지워지지 않게 한다. 원본 제목·가수도 전송하지 않으며 표시명만 편집한다. 기존 MR 메타데이터 캐시/검색 선택을 재사용한다. 가사는 모든 화면 크기에서 표시하고 검색 링크를 같은 탭에 둔다.

취소·Esc·배경 클릭은 같은 변경 확인을 거쳐 보기로 돌아간다. 변경이 없으면 저장은 비활성, 저장 중에는 입력·취소·이탈을 차단한다. 저장 실패는 입력을 유지하고 오류를 표시한다. 성공 시 곡 상세와 대표 MR을 갱신하고 보기로 복귀해 수정 버튼으로 포커스를 돌린다. 편집 세션의 초기값을 고정해 외부 prop 변경이 입력을 덮지 않게 하고 페이지 이탈에는 beforeunload 경고를 사용한다. 기존 `/api/songdetails/[id]` PUT 권한 정책은 변경하지 않았다.

QA의 `?detail`은 실제 SongDetailModal/편집 폼을 렌더링하되 플레이어·외부 부가기능·DB는 가짜로 대체한다. 변경 확인 거절/승인, 배경 취소, 저장 실패/저장 중 보호, 저장 후 보기 복귀, 1440px 가사 표시와 390px 다크 화면 단일 스크롤, 관리자 신규/수정 회귀를 확인한다.

### 메타데이터 입력 UX

공통 `SongMetadataControls`를 양쪽 편집 화면에서 사용한다.

- 언어는 하나의 segmented 선택 영역에 언어 코드·이름으로 표시한다. 데스크톱은 6열, 모바일은 3열이며 선택한 항목만 밝은 표면과 작은 체크로 강조한다. 같은 언어를 다시 누르거나 미설정을 누르면 해제하며 기타 언어도 지원한다.
- 태그는 칩 목록과 개별 삭제 버튼으로 관리한다. Enter·쉼표·추가 버튼, 쉼표/줄바꿈 붙여넣기, 빈 입력의 Backspace 삭제를 지원한다. 한글 조합 중 Enter는 추가로 처리하지 않는다. 중복을 정리하고 미확정 입력도 부모 값에 반영해 저장·탭 이동·이탈 확인에서 누락하지 않는다. 최대 50개/태그당 80자는 기존 저장 스키마로 검증한다.
- 키 조절은 −/＋ 버튼, 직접 입력, 원본 키(0)·미설정(null) 버튼으로 구분한다. 범위는 −12~＋12이며 한계 버튼을 비활성화한다. 직접 입력은 음수와 방향키/Home/End를 지원한다.
- 커버는 부드러운 배경의 작은 미디어 카드로 묶고, 왼쪽에 모바일 64×56 / 데스크톱 80×56 미리보기, 오른쪽에 링크 입력을 배치한다. 입력 중 350ms 대기 후 http(s) 주소만 표시하며 로딩·실패 상태를 제공한다. URL 변경 시 이전 이미지 상태를 초기화하고 클릭하면 원본을 확인할 수 있다. 값을 비워도 미리보기 자리를 유지해 레이아웃 변동을 줄인다.

시각 구성은 표시명 → 분류·검색 → 커버의 위계를 유지하며, 큰 화면에서는 언어와 태그를 나란히 배치한다. 태그 칩과 입력은 한 테두리 안으로 합치고, 보조 안내와 카운터는 작은 중립색으로 낮춘다. 키 조절은 큰 중앙 값과 가벼운 −/＋ 버튼, 원본/미설정 segmented 버튼으로 구성한다. 원본 식별 정보는 기본적으로 접힌 details에 보관한다. 기능·키보드·저장 방식은 유지하며 선택된 부분에만 보라색을 사용한다.

QA는 `/qa/cover.svg` 가짜 이미지를 사용하며 운영 DB 쓰기 없이 관리자 저장과 노래책 저장, 모바일 다크 화면, 이미지 실패·복구, 미확정 태그 저장 및 미저장 보호를 확인한다.
반응형 폭과 요소 밀도를 분리한다. 관리자 wide 편집창과 노래책 편집창은 큰 화면에서 최대 1600px까지 사용한다. 기본 정보의 언어/태그는 lg에서 2열, MR 카드는 xl에서 2열, 가사/메모는 xl에서 2:1로 배치한다. 좁은 화면은 단일 열과 기존 가장자리 8px·라운딩 16px을 유지한다. 언어 약자는 장식 요소로 복원했으며 태그는 칩 행과 입력 행을 분리하되 개별 칩·삭제 버튼 높이를 28px로 낮춘다. 컴팩트한 키 조절은 그대로 유지하고 넓은 화면에서도 위젯만 과도하게 늘어나지 않게 한다. MR 검색/설명·카드 패딩을 줄인 조정은 유지한다.
