# 사용자 화면 UX 검토 + 모션(트랜지션) 기획

작성: 2026-11-16 · 대상: 관리자·게임·OBS·임베드·셀카(`/selfie`, 보류 기능)를 제외한 사용자 화면

검토 방법: 코드 리딩 + dev 서버를 Playwright로 캡처(iPhone 13 390px / 데스크톱 1440px, 라이트·다크) + SSR HTML 분석.

한계: dev 서버 기준이라 **프로덕션의 실제 로딩 시간은 측정하지 않았다.** 로그인 상태 화면(프로필, 플레이리스트 편집)과 재생 중 플레이어, 클립 상세는 캡처하지 못해 코드로만 확인했다. 실기기(iOS/Android) 확인도 안 했다.

### B. 일관성

- **오버레이 구현이 네 가지 방식**으로 섞여 있다(15개 안팎): Headless UI(더보기, 구간 편집) / framer-motion + AnimatePresence(클립 상세, 확인창, 프로필 모달 4종) / framer-motion인데 exit가 동작하지 않음(곡 상세, 로그인 안내) / 애니메이션 없는 수제 포털(신고, 유튜브 안내, 알림 설정). 시간(0.18·0.2·0.3초)과 스케일(0.9·0.98)이 제각각이고 포커스 가두기·스크롤 잠금·ESC 처리도 다르다.
- **모션 감소 설정**(`prefers-reduced-motion`)을 따르는 파일이 7개뿐이다.
- 같은 `/player` 화면을 데스크톱 내비는 '플레이어', 모바일 탭과 페이지 제목은 '보관함'이라고 부른다. 하나로 통일.
- 토스트가 모바일에서도 오른쪽에서 튀어나온다(모바일에서는 화면 폭 전체라 위에서 내려오는 편이 자연스럽다).
- 좋아요 안 한 하트가 회색으로 채워져 있어 비활성처럼 보인다(외곽선 하트가 관례).
- 카드의 호버 떠오름은 터치에서 동작하지 않는다. 누름 피드백(`:active`)이 필요하다.

### C. 잘 되어 있는 것 (유지)

하단 탭 + 안전 영역 처리, 44px 터치 타깃, 다크 모드 완성도, 더보기 시트의 끌어서 닫기, 영상 스테이지를 다시 마운트하지 않는 플레이어 구조, 데스크톱 내비 밑줄 `layoutId`, 홈 히어로 구성.

## 2. 트랜지션 기술 조사 (2026-11 기준)

| 기술 | 상태 | 이 사이트에서의 용도 |
|------|------|----------------------|
| **View Transitions API** (같은 문서) | 2025-10부터 Baseline(Chrome 111, Safari 18, Firefox 144). 미지원 브라우저는 그냥 즉시 전환되어 안전하다. | 페이지 전환, 공유 요소 모프(썸네일 → 상세), 탭 표시 이동, 테마 전환 |
| React `<ViewTransition>` + Next `experimental.viewTransition` | Next 문서상 아직 실험 기능, 프로덕션 비권장. 현재 15.5.19에서는 React 실험 채널이 필요하다. | 지금은 보류. Next를 올릴 때 교체 대상 |
| **Motion(framer-motion 12)** `layout` / `layoutId` / 드래그 | 이미 의존성에 있음. 중단 가능, 스프링, 제스처 추적 | 플레이어 펼침, 바텀시트, 세그먼트 표시, 좋아요 |
| CSS `@starting-style` + `allow-discrete` | 2024-08부터 Baseline | 드롭다운·툴팁 같은 작은 팝업의 등장/퇴장 (JS 불필요) |
| CSS 스크롤 연동 애니메이션 `animation-timeline: view()` | web.dev 2026-10 글 기준 Firefox 159에서 기본 활성 → 막 Baseline. 최근 일이라 `@supports`로 감싸 점진 적용 | 랜딩 스크롤 리빌(A1 해결에도 도움) |
| CSS `linear()` 이징 | Baseline | CSS 전환에 스프링 느낌 부여 |
| `interpolate-size` (height:auto 애니메이션) | Baseline 아님 | 쓰지 않음 |

판단 기준 하나: **View Transition은 진행 중 조작을 막고 중간에 끊을 수 없다.** 그래서 손가락을 따라가야 하는 것(시트, 플레이어 끌어내리기)은 Motion으로, 한 번에 끝나는 화면 교체는 View Transition으로 나눈다.

## 3. 기획 — 어디에 어떤 효과를

### 모션 원칙 (토큰)

- 시간: 누름 100ms · 호버/페이드 160ms · 페이지/다이얼로그 진입 220ms · 시트/큰 모프 320ms. **퇴장은 진입의 약 70%.** 화면 이동은 300ms를 넘기지 않는다.
- 이징: 진입 `cubic-bezier(0.2, 0, 0, 1)`, 퇴장 `cubic-bezier(0.4, 0, 1, 1)`. 스프링은 두 종: 빠른 것 `{stiffness: 380, damping: 32}`(이미 내비 밑줄에 비슷한 값 사용), 시트 `{stiffness: 320, damping: 34}`.
- `transform`과 `opacity`만 움직인다. `backdrop-filter` 값 자체는 애니메이션하지 않는다(블러된 레이어의 투명도만).
- 모션 감소 설정 시: 이동·스케일 제거, 짧은 페이드만. 루트에 `MotionConfig reducedMotion="user"` + CSS 미디어쿼리.
- 위치: `src/shared/motion/`(토큰, 훅, 공용 Sheet) + `globals.css`의 CSS 변수.

### 시그니처 전환 (효과가 큰 순)

**S1. 미니 플레이어 ↔ 전체 플레이어 모프** — 이 사이트를 가장 '앱'처럼 보이게 할 한 가지.

- 영상 스테이지가 왼쪽 아래 바 자리에서 상단 큰 자리로 이어져 커진다(Motion `layout`, 시트 스프링). 스테이지는 지금도 같은 요소라 영상이 끊기지 않는다.
- 오버레이는 아래에서 올라오고, 블러 아트워크 배경은 페이드, 컨트롤·재생목록은 40ms 간격으로 순차 등장.
- 모바일: 아래로 끌면 손가락을 따라 내려가며 접힌다(더보기 시트의 `shouldDismissSheet` 재사용 + 속도 판정).
- 곡이 바뀔 때 제목·아티스트는 위아래로 교차 페이드, 배경 아트워크는 400ms 크로스페이드.

**S2. 페이지 전환** — View Transitions. Next 15.5에서는 `document.startViewTransition`을 직접 감싼 `TransitionLink` 모듈 하나로 구현한다(나중에 React `<ViewTransition>`으로 바꿔 끼울 수 있게 한 곳에 격리).

- 탭 간 이동(홈·노래책·클립·보관함): **페이드 스루** — 나가는 화면 90ms 페이드아웃, 들어오는 화면 페이드 + 8px 상승 210ms. 좌우 슬라이드는 쓰지 않는다(탭은 동등한 관계).
- 드릴인(클립 목록 → 클립, 보관함 → 플레이리스트, 노래책 → 플레이리스트): 들어갈 때 새 화면이 오른쪽 24px에서 밀려 들어오고, 상단 뒤로 화살표로 나올 때는 반대 방향. 방향은 `<html data-nav="forward|back|tab">`로 구분한다(Firefox의 transition types 지원이 불확실해서 data 속성 사용).
- **헤더·하단 탭·미니 플레이어는 움직이지 않는다.** 각각 `view-transition-name`을 줘서 페이지 스냅숏에서 분리. 미니 플레이어는 재생 중 영상이 멈춘 그림으로 보이지 않도록 old 스냅숏을 숨기고 live 쪽만 보여 준다.
- **탭 표시 이동**: 하단 탭의 활성 배경 알약과 데스크톱 밑줄에 이름을 주면, 내비가 페이지마다 다시 마운트되는 현재 구조 그대로도 탭 사이를 미끄러져 이동한다.
- 전제: A3의 `loading.tsx`. 없으면 서버 응답 동안 이전 화면이 얼어 있는다.

**S3. 공용 시트/다이얼로그** — Headless UI `Dialog` + Motion 패널 하나로 통일.

- 모바일: 바텀시트. 스프링으로 올라오고, 손잡이·헤더를 끌어 닫는다. 배경은 160ms 페이드.
- 데스크톱: 가운데 다이얼로그. 0.96 → 1 스케일 + 8px 상승 220ms, 퇴장 150ms.
- A2(뒤로가기), 포커스, 스크롤 잠금, ESC를 여기서 한 번에 해결. 곡 상세·클립 상세·확인창·신고·플레이리스트 추가·프로필 모달을 순차 이전.
- 무거운 내용(유튜브 iframe)은 진입 애니메이션이 끝난 뒤 마운트해 프레임 드랍을 막는다.

**S4. 공유 요소 모프**

- 클립 카드 썸네일 → 클립 상세의 플레이어 자리 (View Transition, 누른 카드에만 이름 부여).
- 보관함 플레이리스트 커버 → 플레이리스트 상세 헤더 커버.
- (선택) 곡 카드 → 곡 상세: 카드가 그 자리에서 커지며 시트가 된다(`layoutId`). 화려하지만 571곡 목록에서 성능 확인이 필요해 마지막 단계로.

**S5. 테마 전환 원형 확산** — 토글 버튼 위치에서 새 테마가 원으로 퍼져 나간다(View Transition + `clip-path: circle()` 450ms). 구현이 작고 인상이 크다.

### 하지 않을 것

데스크톱 전체 화면 슬라이드, 300ms 넘는 화면 전환, 수백 개 항목의 `layout` 애니메이션, 스크롤 하이재킹, 패럴랙스 추가. 화려함보다 "빠르고 끊기지 않음"이 세련됨의 대부분이다.

### 확인이 필요한 위험

- View Transition 중 유튜브 iframe·치지직 영상 스테이지가 끊기지 않는지 — 실기기 확인 필요. 문제가 있으면 플레이어가 떠 있는 동안은 페이지 전환을 단순 페이드로 낮춘다.
- 브라우저 뒤로가기(popstate)에는 수동 래퍼로 전환을 걸 수 없다. 뒤로 화살표 버튼만 역방향 전환이 되고, 브라우저 뒤로가기는 즉시 전환된다.
- iOS Safari의 가장자리 스와이프 뒤로가기는 자체 애니메이션이 있어 View Transition과 겹치면 두 번 움직여 보일 수 있다 — 실기기 확인.
- 저사양 안드로이드에서 `backdrop-blur` + 시트 스프링 프레임 유지 여부.
