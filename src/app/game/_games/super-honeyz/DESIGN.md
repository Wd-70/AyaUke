# 슈퍼 허니즈 — 디자인 문서

마리오 1의 스테이지·게임 방식 + 최신 시리즈의 조작감을 목표로 하는
프로젝트 아이(허니즈·아카시아) 팬게임.

## 조작감 (즉답형 모던 튜닝)

설계 철학: **입력 즉시 반응** — 가속·제동 거리를 짧게 잡아 미끄럽거나 무거운 느낌을 없앤다.
※ SMB3식 P게이지는 "풀스피드 유지 보상" 구조가 가감속을 느슨하게 만들어 조작감을 해쳐서 **제거함** (2026-06-12).

- **즉답 가감속**: 0→달리기(175) 0.15초, 키 떼면 ~0.12초 정지 (`ACCEL 1200` / `DECEL 1500`)
- **스프린트(2단 가속)**: 달리기 최고속 도달 후 0.5초 더 유지하면 최고속 +40% (175→245, 체감 ~1초). SMB3 원작 비율(걷기:달리기:대시 = 3:5:7, 대시=달리기×7/5). 기본 즉답성 위에 고점만 얹음. 게이지 UI 없이 풀차지 시 양팔 벌린 모션(prun) + 발밑 반짝이로 표현. 공중에서 유지(점프로 안 끊김), 지상에서 조건 깨지면 0.35초 내 소멸.
- 코요테 타임 0.08s / 점프 버퍼 0.12s
- 가변 점프 높이 (버튼 릴리즈 시 상승 컷 + 저중력/고중력 전환), 달리기 속도 비례 점프력 보너스
- **자유로운 공중 제어** (모던 방식): `AIR_ACCEL 1000`, 반대로 꺾을 땐 `AIR_TURN_ACCEL 2000`으로 즉시 전환. ※SMB1 원작은 오히려 공중 모멘텀이 제한적이라, 일부러 모던 방식 채택.
- **에이펙스 모디파이어**: 점프 정점 부근(`|vy|<APEX_WINDOW`)에서 중력 `×0.5` → 체공감 (Celeste/모던 마리오 기법)
- **코너 보정**: 상승 중 머리가 블록 모서리에 ≤`CORNER_CORRECT`px만 걸리면 옆으로 밀어 통과 (머리 쿵 방지)
- **스키드 래치**: 달리기 중 반대 입력 시 한번 시작되면 **완전히 멈출 때까지** `SKID_DECEL 700`로 제동(~0.25s, 모션이 보임) 후 반대 가속. 걷기 속도 이하의 방향 전환은 스키드 없이 즉시.
- 자유 후방 카메라 스크롤
- 튜닝값은 전부 `game/constants.ts`에 모여 있음
- 회귀 테스트: `game/__tests__/player-physics.test.ts` (가감속·스키드·공중전환·에이펙스·코너보정 7케이스)

## 연출

- 파워업/피격 변신: 월드 전체 정지 + 크기 교차 깜빡임 (원작 스타일)
- 클리어: 깃대 슬라이드 + 깃발 하강 → 성까지 걷기 → 남은 타임 점수 정산
- 깃대 점수: 잡은 높이에 따라 100~5000점

## 캐릭터

### 컨셉: 멤버 구출 & 교체

스테이지를 진행하며 멤버를 한 명씩 구출 → 로스터에 추가 → 교체해서 플레이.
캐릭마다 고유 능력이 있어 특정 구간을 특정 캐릭으로 수월하게 돌파 가능.
교체 방식: 맵 입장 시 선택 또는 자유 교체 (둘 다 지원 가능한 구조로 설계, 추후 확정).
미결: 교체 시 파워업(1단/2단) 상태 승계 여부 — 자유 교체면 "공유 승계" 추천.

**기본 동작(서기·걷기·달리기·점프·스키드·사망)은 전 캐릭 공통** — 캐릭별 시트 필요.
고유 능력용 추가 스프라이트만 캐릭별로 2~4포즈씩 선별 제작.

## 구조

```
super-honeyz/

  game/
```

동기화하고 변환 행렬로 확대 — 텍스트·도형이 최종 해상도에서 래스터되어 선명.

## 에셋 파이프라인

AI 생성(ChatGPT, '시원한 수박' 프로젝트) 픽셀아트 → 후처리 → 게임 반영.

1. 생성: 레퍼런스(`asset-src/reference/`)를 클립보드로 첨부, **마젠타(#FF00FF) 크로마키 배경**으로 생성. 한 동작은 가로 스프라이트 시트로 한 번에 뽑는 게 프레임 일관성에 유리.
2. 원본 보관: `asset-src/generated/` (gitignore)
3. 가공: `node scripts/assets/process-sprites.mjs <입력> <이름> <프레임수>`
   - 마젠타 → 투명, 빈 열 기준 프레임 분할, 바운딩박스로 발·중앙 정렬, 96px로 다운스케일
   - 출력: `public/game/super-honeyz/<이름>.png` + `.json`(frameWidth/Height/frames)
4. 게임 로드: `game/sprites.ts`의 `loadSheet`/`drawFrame`, `Game.drawPlayer`에서 상태별 프레임 선택(서기/걷기4프레임/점프). 로드 전엔 도형 폴백.

### 색 일관성 (중요)

동작들을 따로 생성하면 머리색 등 팔레트가 미세하게 드리프트됨. **여러 동작을 한 장의
그리드 시트로 같이 생성하면 팔레트가 강제로 통일**되어 해결. → 큰폼 7종을 4행 그리드
한 장으로 생성 후 `scripts/assets/process-grid.mjs` 로 2D 슬라이싱.

```
node scripts/assets/process-grid.mjs <그리드png> "stand,skid,jump,death;walk:4;run:4;prun:4"
```
- 행(빈 가로줄) → 칸(빈 세로줄) 2D 분할, 전체 공통 셀 크기(발 정렬+가로중앙)로 통일 →
  모든 출력이 같은 frameWidth/Height(73×96) → 게임에서 단일 스케일로 사용

현재 반영됨(큰 폼 아야): `stand` / `walk`(4) / `run`(4) / `prun`(4) / `jump` / `skid` / `death`.
`Game.drawPlayer`가 상태(사망>공중>스키드>속도)로 시트 선택 — `prun`은 달리기 최고속 부근(92%↑)에서 전력질주 모션으로 사용.
작은 폼은 같은 스프라이트를 축소해서 사용 중(전용 도트는 추후). 빨간 니트 폼·적·아이템 도트는 미정.
